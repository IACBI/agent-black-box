# Security Policy

Security fixes target the latest released version. The supported runtime is Node.js 22 or newer, as declared in `package.json`.

## Report a vulnerability

Report privately through the [GitHub Security page](https://github.com/IACBI/agent-black-box/security) when available. Otherwise, use an existing private maintainer contact channel before publishing exploit details.

Include affected versions, reproduction steps, impact, and possible data exposure. Use redacted or synthetic examples; never include real credentials or private repository contents.

## Privacy and trust

Capture-log readers now pin regular file descriptors, bound reads to the opened length plus one byte, and compare exact integer identities and nanosecond timestamps through the end of parsing. Linked/replaced/growing logs fail rather than yielding trusted results. Worktree inspection also rejects rounded-identity collisions and checks the pathname before accepting text. Hook mutations use an exclusive cross-process owner lock; stale/uncertain locks require inspection and replacement locks are never unlinked as cleanup. These measures cover supported races among cooperating operations; they cannot make a hostile same-user filesystem atomic.

Optional `recover --max-rss-mb` / `FinalizeSessionOptions.maxRssBytes` observes whole-process RSS during live-wrapper polling and at chunk, record-retention and phase checkpoints. Refusal before finalization leaves primary evidence/ownership intact; in-flight readers settle before releasing their claim. This supplements byte/count quotas and does not cap instantaneous RSS or child-process memory. OS-enforced isolation is required for hard containment; V8/worker heap limits exclude other memory. See [Node process memory](https://nodejs.org/docs/latest-v22.x/api/process.html) and [worker resource limits](https://nodejs.org/docs/latest-v22.x/api/worker_threads.html).

Recovery also accepts `--max-records` (or `FinalizeSessionOptions.maxRecords`) to bound the combined number of retained accepted records before array insertion. Combine it with the byte allowance to constrain many-small-record workloads. Invalid options fail before mutation; count refusals preserve logs and ownership and permit a sufficient-budget retry. Defaults and stored formats remain unchanged. Neither quota bounds parsed-object size, transient parsing allocations, or process RSS. See [recovery guidance](docs/USAGE.md#record-and-finalize) for operational precautions.

Evidence stays local: Agent Black Box has no telemetry and does not upload repository data or capture terminal output. Credential detection remains heuristic; review reports before sharing. Optional independently anchored evidence signatures and bounded custom-pattern execution are described in [Evidence security](docs/EVIDENCE-SECURITY.md). Repository and session storage must be trusted: processes with the same filesystem access can race checks or alter evidence.

`abb run` and `recordAndRunCommand` execute selected commands with their existing permissions. Programmatic callers must authorize executable names and arguments; recording is not a sandbox. Native executables run without a shell. On Windows, `.cmd`/`.bat` scripts run through `cmd.exe` with quoted arguments; percent signs, line breaks, and NUL are rejected, and regression tests cover injection payloads. On Windows, bare command names and the Git executable resolve only through absolute PATH entries, never from the repository being reviewed, because process creation otherwise searches the current directory first; tests verify that a planted `git.exe` is not executed.

Tool-specific credential detection follows explicit `env`, `sudo`, `nohup`, `nice`, and `timeout` prefixes with supported options, including mixed nested wrappers. Ambiguous options, shell modes, split strings, or prefixes exceeding 128 arguments or eight wrappers hide the wrapper arguments. Docker/Podman credential flags are applied only after their actual `login` subcommand, with known global-option operands kept separate. Execution always receives the original arguments; arbitrary shell strings and other wrappers are not parsed as tool invocations.

`applyRollbackPlan` bypasses the CLI's snapshot preflight. Callers must validate and obtain appropriate confirmation before restoring files.

Git subprocesses preserve selected local storage and discovery environment variables, including alternate indices. Executable and configuration injection variables are filtered by `simple-git`, and the one `git cat-file --batch` process that reads staged blobs receives the same filtered environment; trusted repository configuration remains a separate trust boundary. Terminal presentation escapes control characters in repository paths and other untrusted values. Derived Markdown and pull request comments show C1 controls (U+0080–U+009F), Unicode line/paragraph separators, and bidirectional controls as visible escapes, including command labels, Git snippets, and capture warnings. Structured JSON/SARIF retain their original values, and manual rollback snippets preserve exact arguments using POSIX shell quoting.

Ambient `GIT_LITERAL_PATHSPECS`, `GIT_GLOB_PATHSPECS`, `GIT_NOGLOB_PATHSPECS`, and `GIT_ICASE_PATHSPECS` are removed so repository exclusions, literal baseline paths, and rollback selectors keep their defined grammar. Analysis preserves backslash characters in POSIX filenames and treats them as separators on Windows. Recovery/finalization require a regular session child at its expected physical location before claim, marker, or report writes. Archive destinations are physically checked before directory creation. These checks retain trusted repository/storage aliases and do not provide an atomic guarantee against concurrent hostile directory substitution.

Location is checked again before rollback/report publication. If it changes, finalization retains its uncertain claim instead of unlinking through a replacement alias. Recovery then requires restoring trusted storage and the failed finalizer's exit; normal quota/deadline refusals retain their existing retry behavior.

File exports publish complete content before it becomes visible at the destination. Without `--force`, exclusive hard-link publication preserves a concurrently created destination and requires filesystem hard-link support and permission; failures do not fall back to a partial copy. Forced exports use atomic replacement and replace a destination leaf symlink without writing through it.

On POSIX, atomic file publication also synchronizes the containing directory after publication and temporary-file cleanup. Finalization flushes existing event/command logs before completion metadata, and cleanup synchronizes the receipt directory and session-root entry before removing active state, then synchronizes shared state before and after releasing the lock. I/O, permission, and unsupported directory-sync errors are propagated; retries preserve the ownership proof until the start barrier can safely be released. A directory-sync failure can occur after a complete file was published, so a failed write does not imply an absent destination. Windows retains file-content synchronization and process-interruption recovery: Node does not provide portable Windows directory-entry synchronization. Filesystem/device behavior and newly created ancestor directories still prevent a universal power-loss guarantee.

Finalization reserves accepted canonical record bytes before retaining records, sharing the existing 256 MiB report allowance between event and command logs. Unknown accepted fields are included. The quota excludes parsed-object/core/stream overhead and is not an RSS limit. `recover --max-record-bytes` can lower this allowance; `recover --command-wait-timeout-ms` can bound live-wrapper waiting. Refusals preserve primary ownership, command markers, and raw logs rather than publishing partial reports. All started readers settle before finalization ownership is released. Default waiting remains unlimited.

`secretPatterns` come from repository configuration. Length, backreferences, nested quantifiers, syntax, and empty matches are screened. Execution is isolated in a resource-limited worker with an evaluation deadline; scanning fails explicitly on exhaustion and redaction hides the full input. Custom detection inspects only the first 4,096 characters of each line. `secretAllowlist` entries require a reason and hide only possible-secret findings; the count of hidden findings is reported. See [Evidence security](docs/EVIDENCE-SECURITY.md) for exact bounds and remaining limitations.

When custom rules are configured, command redaction combines their original-input matches with original built-in and embedded-script credential ranges. Overlapping matches are merged before text is changed; a partial custom pattern cannot invalidate a complete recognized credential. Structural URL/JSON/assignment/tool-flag transformations conservatively hide the whole argument when an original custom match could be invalidated. Unmatched custom patterns preserve existing formatting, worker exhaustion redacts the entire input, and execution always receives the original arguments.

`abb hook install` writes into the repository's effective hooks directory only when it is inside the repository, always refuses symbolic links, and refuses foreign hooks unless forced (keeping a backup). It checks configuration and the selected policy before changing hooks. An explicit global `--allow-external-session-dir` at installation persists that authorization as a fixed hook argument; repository configuration alone cannot authorize external storage, and network paths remain blocked. The policy name is validated before it reaches the shell script. The first commit keeps its high-severity fallback unless `--first-commit policy` explicitly selects the configured gates. Initial analysis requires an unborn HEAD and staged content. The hook fails open when `abb` is not on PATH. A configured `retention.archiveDir` must stay inside the repository; an external archive destination needs an explicit `--to`.

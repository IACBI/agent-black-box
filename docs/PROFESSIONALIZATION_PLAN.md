# Professionalization plan

This plan builds on the completed audit and preserves existing CLI commands, report fields, and the readable `session.json` format for ordinary sessions. Work is sequenced by user impact and by the evidence needed to make each change safe.

| Priority | Work                      | Decision and acceptance evidence                                                                                                                                                                                                                                                                                                                                    |
| -------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1        | Large-session reliability | Define one size policy shared by report writing and reading. Keep append-only raw observations intact. A completed report must always be readable by the catalog; an over-budget session must fail explicitly without pretending that evidence is complete. Test the boundary, recovery, and legacy reports. Avoid an unbounded JSON parse or a silent record drop. |
| 2        | Staged review baseline    | Add an explicit baseline comparison to `analyze --staged`. Compare stable finding identities, disclose what was skipped on either side, and keep secret values out of output. Test staged, unstaged, renamed, deleted, and invalid-reference cases.                                                                                                                 |
| 3        | History usability         | Add bounded catalog filters without opening every full report. Add retention _planning_ with a default preview, explicit confirmation for deletion, and protection for active, incomplete, and corrupt sessions. Test path containment and interrupted deletion.                                                                                                    |
| 4        | Performance and CI        | Measure report writing/catalog fallback and large-repository analysis in addition to NDJSON ingestion. Keep realistic, non-flaky budgets. The existing Windows/Linux/macOS and Node 22/24 workflow must pass on GitHub; local tests alone cannot establish that result.                                                                                             |
| 5        | Documentation and release | Update CLI help, usage, report format, migration/recovery notes, and the audit risk register. Run format, lint, typecheck, dead-code analysis, build, tests, dependency audit, performance budgets, and package validation.                                                                                                                                         |

The large-report decision comes first because adding history and comparison features on top of a report that cannot be reopened would compound the reliability problem. Storage format changes require versioning and backward compatibility; a simple increase to the 32 MiB reader limit is not an acceptable final design because it moves the failure point and increases memory use without a defined bound.

Progress: the large-report path now keeps full `session.json`, writes a compact replay sidecar above 32 MiB, validates reconstructed records, supports bounded legacy fallback, and refuses reports above 256 MiB without claiming completion. Staged baseline comparison uses count-aware matching of unchanged secret-like lines and Git-identified rename sources where available. Command metadata redaction covers known structured credentials without changing the executed arguments. History filters use a bounded search index with a legacy fallback. Retention previews older completed sessions and requires typed confirmation plus a fresh safety check for deletion. Expanded local performance budgets, the full quality check, dependency audit, package inspection, and release metadata validation passed. Draft PR #50 passed hosted CI across Linux, macOS, and Windows on Node 22 and 24, including CodeQL.
